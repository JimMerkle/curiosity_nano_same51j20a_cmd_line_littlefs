# MCC "Overwrite Source Code" Warning � Root Cause & Fix

## The Warning Dialog

```
Another project with same config name already exists in
C:\Work\Sources_GIT\curiosity_nano_same51j20a_cmd_line_littlefs\src\config\default .
If you continue, it might overwrite the existing code. Would you like to continue?
```

## Root Cause

MCC stores project configuration in a subfolder named `{ProjectName}_default/`
inside the `.X` project directory. The required structure is:

```
LittleFS.X/
    LittleFS_default/
        mcc-config.mc4        <- peripheral config + file hash map
        components/           <- per-peripheral YAML files (cmsis, core, sercom1, ...)
```

When `LittleFS_default/` is absent (e.g. after a fresh git clone where components/
and mcc-config.mc4 sit at the project root), MCC uses a fallback path that checks
its global session registry for any prior project that used config folder name "default".
Finding one, it shows the "same config name" warning.

Clicking Yes on that dialog causes MCC to create a new EMPTY `LittleFS_default/`
and load a blank configuration. It does NOT pick up the existing mcc-config.mc4
from the root, so all peripherals appear missing.

## The Fix

Move `mcc-config.mc4` and `components/` into `LittleFS_default/`:

```sh
# Use filesystem move + git add -A (git mv has issues with directory targets in PowerShell)
mkdir LittleFS.X\LittleFS_default
move LittleFS.X\mcc-config.mc4  LittleFS.X\LittleFS_default\mcc-config.mc4
move LittleFS.X\components       LittleFS.X\LittleFS_default\components
git add -A LittleFS.X/
```

Final structure:

```
LittleFS.X/
    LittleFS_default/
        mcc-config.mc4
        components/
            cmsis.yml  core.yml  dfp.yml  evsys.yml  nvmctrl.yml
            sercom1.yml  sercom2.yml  sercom5.yml  tc0.yml
    nbproject/
```
(`mcc-manifest-*.yml` files are autogenerated locally by MCC — gitignore both.)

## Reference: working baseline

The `curiosity_nano_same51j20a_command_line` repo already has the correct structure:

```
command_line.X/
    command_line_default/
        mcc-config.mc4
        components/
    mcc-manifest-autosave.yml
    mcc-manifest-generated-success.yml
```

Use this as the template for any new MCC/Harmony project.

## .gitignore

Both manifest files are autogenerated and transient — gitignore both:

```
**/mcc-manifest-autosave.yml
**/mcc-manifest-generated-success.yml
```

- `mcc-manifest-autosave.yml` — rewritten every MCC run.
- `mcc-manifest-generated-success.yml` — written on successful generation, but also
  autogenerated. Neither file is the root cause of nor the solution to the warning.

The `command_line` reference repo gitignores both (confirmed).

## Confirmation

After the fix MCC opens correctly and loads all configured peripherals:
BSP_SAM_E51_Curiosity_Nano, SERCOM1 (SPI master), SERCOM2 (USART), SERCOM5 (USART),
TC0, EVSYS, NVMCTRL, CMSIS, core, dfp.
